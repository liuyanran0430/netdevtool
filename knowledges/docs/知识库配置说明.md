# 知识库配置说明

> 适用范围：知识设置页「向量与检索配置」页签。
> 配置对象：顶部选中的知识库。每个知识库对应一个独立向量库，配置只对当前知识库生效。

---

## 1. 配置概览

页面分为三块：

| 区块 | 作用 | 影响阶段 |
|---|---|---|
| 分段模式 | 决定文档如何切成块 | 文档入库 / 重建索引 |
| 索引模式 | 决定块的索引方式与成本 | 文档入库 / 重建索引 |
| 检索设置 | 决定提问时如何召回内容 | 每次问答检索 |

配置保存在 `knowledge_bases` 表中，按知识库维度存储：

| 页面项 | 数据表字段 |
|---|---|
| 分段模式 | `chunking_mode` |
| 通用分隔符 / 最大长度 / 重叠 | `general_delimiter` / `general_max_length` / `general_overlap` |
| 父块分隔符 / 最大长度 | `parent_delimiter` / `parent_max_length` |
| 子块分隔符 / 最大长度 | `child_delimiter` / `child_max_length` |
| 索引模式 | `indexing_mode` |
| 检索方式 | `retrieval_mode` |
| 语义权重 | `hybrid_semantic_weight` |
| Top K | `hybrid_top_k` |
| Score 阈值 | `hybrid_score_threshold` |
| 创建 / 更新时间 | `created_at` / `updated_at` |

点击「保存」后配置写入数据库。页头显示「已读取配置」表示当前内容与库中一致；有改动时显示「有未保存修改」。

## 2. 分段模式（Chunking Strategy）

分段的目标是同时兼顾两件事：**检索要准**（块不能太大）、**回答要有上下文**（块不能太碎）。

### 2.1 General 通用文本分段

按分隔符把文档切成大小相近的块，适合结构清晰、篇幅较短的文档。

| 参数 | 含义 | 默认值 | 取值范围 |
|---|---|---|---|
| 分隔符 | 在什么位置切开文本 | `\n\n` | 非空，支持 `\n`、`\n\n`、`#`、`---` 等 |
| 最大分段长度 | 单块最多多少 token | 500 | 20–5000 |
| 分段重叠 | 相邻块重复的 token 数 | 50 | ≥ 0，且小于最大分段长度 |

**怎么设：**

- 命令说明、FAQ、短段落：分隔符 `\n\n`，长度 300–500，重叠 30–50。
- 以标题分节的 Markdown：分隔符可用 `#` 或 `##`，长度 500–800，重叠 50–80。
- 长段落连续叙述：长度 500–800，重叠 80–120，避免一句话被切断后语义缺失。
- 重叠不要超过最大长度的 20%，否则索引体积和重复召回会明显增加。

**适用：** 命令参考中的单个功能说明、FAQ、短篇操作说明。
**不适用：** 动辄几十页、需要“小块检索、大块回答”的长手册。

### 2.2 Parent-Child 父子分段（推荐用于长手册）

把文档切成两层：

- **子块（Child）**：切得细，用于向量检索，保证命中准确。
- **父块（Parent）**：范围更大，命中子块后把整个父块交给大模型，保证上下文完整。

| 参数 | 含义 | 默认值 | 建议 |
|---|---|---|---|
| 父块分隔符 | 父块切分边界 | `\n\n` | 章节或段落边界 |
| 父块最大长度 | 父块 token 上限 | 1000 | 1000–1500，需 ≥ 子块 |
| 子块分隔符 | 子块切分边界 | `\n` | 更细粒度，如换行、句号 |
| 子块最大长度 | 子块 token 上限 | 200 | 200–500 |

**怎么设：**

- 厂商配置手册、命令参考：父块 1000–1500，子块 200–300，父块用 `\n\n`，子块用 `\n`。
- 故障排查文档：父块 1200 左右，子块 300 左右，保证一个故障案例的步骤不被拆散。
- 子块长度不建议超过 500，否则检索精度下降；父块不建议超过 1500，否则大模型上下文浪费明显。
- 父块必须大于子块，否则父子结构没有意义。

**适用：** 命令参考、配置指南、故障排查手册等长文档。
**代价：** 索引和存储量比通用分段更大，但问答质量通常最好。

### 2.3 Q&A 问答对

识别 Markdown 或 Excel 中的问答结构，按“一问一答”切片入库。

- Markdown 建议使用统一格式，例如 `## Q-001` 加 `**Q：**` / `**A：**`。
- Excel 建议一行一条，列为“问题、标准答案、厂商、型号、版本、来源”等。
- Q&A 模式不需要额外配置分隔符和长度，命中后直接返回对应答案，精度最高。

**适用：** 高频问题库、标准答复、产品 FAQ。
**不适用：** 操作步骤很长、需要多段组合回答的内容。

### 2.4 如何选择

| 文档类型 | 推荐模式 | 理由 |
|---|---|---|
| 高频 FAQ / 标准问答 | Q&A | 一问一答，命中即答案 |
| 命令参考 / 配置手册 | Parent-Child | 子块精准命中，父块补全上下文 |
| 故障排查 SOP | Parent-Child 或 General | 一个案例或一个步骤组作为完整块 |
| 短篇说明、术语表 | General | 结构简单，成本低 |
| 混合类型知识库 | Parent-Child | 兼容性最好，后续可单独优化 |

## 3. 索引模式（Indexing Mode）

| 模式 | 说明 | 优点 | 代价 |
|---|---|---|---|
| 高质量 | 调用多模态嵌入模型处理文本/图片 | 语义召回效果好，支持图片内容 | 消耗 Token 和算力，建库慢 |
| 经济 | 仅提取关键词建立索引 | 成本低、速度快 | 只能靠关键词匹配，语义能力弱 |

**怎么选：**

- 生产环境、面向用户的问答库：选「高质量」。
- 纯命令查询、术语查询，且文档量很大、成本敏感：可选「经济」。
- 同一知识库内不要频繁切换索引模式；切换意味着全量重建索引。

## 4. 检索设置（Retrieval Settings）

### 4.1 三种检索方式

| 方式 | 原理 | 适合 |
|---|---|---|
| 向量检索（embedding） | 把问题和块转成向量，按语义相似度召回 | 口语化提问、同义表达、跨厂商说法不一致 |
| 关键词检索（bm25） | 按词频和逆文档频率匹配关键词 | 精确命令、型号、版本号、参数名 |
| 混合检索（hybrid） | 同时执行向量和关键词检索，融合后重排序 | 网络设备文档的默认选择 |

网络设备场景建议默认使用**混合检索**：既能理解“VLAN 间不通”这类口语问题，也能准确命中 `port default vlan`、`display vlan` 这类命令。

### 4.2 混合检索参数

| 参数 | 含义 | 默认值 | 取值范围 |
|---|---|---|---|
| 语义权重 | 向量检索结果在融合中的占比 | 50% | 0–100，关键词权重自动为剩余比例 |
| Top K 召回数量 | 一次召回多少条候选块 | 3 | 1–50 |
| Score 匹配阈值 | 低于该相似度的结果被丢弃 | 0.60 | 0–1 |

**怎么调：**

- **语义权重**
  - 50%：语义和关键词均衡，适合大多数问答。
  - 60%–70%：用户提问口语化、同义表达多时提高。
  - 30%–40%：查命令、型号、版本号等精确内容时降低。
- **Top K**
  - FAQ：3–5 条足够。
  - 命令参考、配置手册：5–8 条，给重排序更多候选。
  - 不建议盲目调大，候选过多会引入噪声并增加延迟。
- **Score 阈值**
  - 0.55–0.65 是常用区间。
  - 阈值过高会“什么都搜不到”，表现为回答频繁说“未找到相关内容”。
  - 阈值过低会召回大量弱相关内容，表现为答案跑题。
  - 调整时每次只改一个参数，用同一组问题对比效果。

> Top K 和 Score 阈值目前只在「混合检索」下生效；选择纯向量或纯关键词检索时，使用各自默认策略。

## 5. 元数据的作用

### 5.1 什么是元数据

元数据是附着在每个文档块上的“描述信息”，不参与正文语义，但决定这个块**能不能被正确筛出来、引用出来、隔离出来**。

本页面配置的知识库名称、向量库名称是元数据的顶层归属；更细的元数据在文档入库、切块、向量化时写入。

### 5.2 推荐字段

| 字段 | 示例 | 作用 |
|---|---|---|
| `kb_id` / `kb_name` | `1` / `厂商配置命令参考库` | 区分知识库，支持多库隔离 |
| `doc_id` | `doc_0012` | 文档级删除、更新、去重 |
| `file_name` | `H3C S6800命令参考.md` | 引用来源 |
| `vendor` | `H3C` | 厂商过滤，避免华为/华三/中兴命令混召回 |
| `product` / `model` | `S6800` | 型号过滤 |
| `version` | `Release 25xx` | 版本过滤，避免新旧版本配置混用 |
| `doc_type` | `command_reference` | 文档类型过滤 |
| `chapter_path` | `VLAN配置 > port default vlan` | 提供章节上下文和引用定位 |
| `command` | `port default vlan` | 命令级精确召回 |
| `view` | `interface` | 区分系统视图、接口视图等 |
| `source_page` | `P123` | 引用回溯 |
| `updated_at` | `2026-11-17` | 判断内容时效 |
| `visibility` | `internal` | 权限和密级控制 |

### 5.3 元数据的六个作用

1. **检索过滤**
   先按 `vendor + model + version` 过滤，再做向量召回，可以避免“问华为却召回华三命令”的问题。

2. **引用与可追溯**
   回答中附带文档名、章节、页码，用户可以核对原文，降低幻觉风险。

3. **去重与版本隔离**
   同一命令在不同版本文档中大量重复。用 `command + version + doc_id` 去重，只保留有效版本。

4. **增量更新与删除**
   文档更新时按 `doc_id` 删除旧块再写入新块，避免新旧内容同时被召回。

5. **权限与租户隔离**
   按 `visibility`、部门或租户过滤，防止越权检索。

6. **评测与知识缺口分析**
   按厂商、型号、文档类型统计召回和未命中情况，定位知识库缺哪类资料。

### 5.4 元数据与切块的关系

元数据不能替代切块，但可以显著提升切块的价值：

- 切块决定“内容怎么分”，元数据决定“内容属于谁、适用于什么范围”。
- 建议把关键元数据拼进向量化文本的头部，例如：

```text
华为 S5735 V200R021C00 命令参考 > VLAN配置命令 > port default vlan
```

这样同一段命令在华为、华三、中兴文档中的向量更容易区分，召回更准。

- 原始正文保持不变，元数据单独存为 payload，检索时用于过滤和展示，不直接拼进回答正文。

## 7. 保存、生效与限制

- 点击「保存」只更新当前知识库的配置记录，不会影响其他知识库。
- 分段模式和索引模式影响的是**入库结果**；修改后需要重新切分文档并重建索引，检索侧才会使用新配置。
- 页面提示「知识库已有文档切分时，不允许修改分段模式和索引模式」。实际调整时应先处理已有文档，或新建知识库验证，避免新旧切分混在一起。
- 检索参数（语义权重、Top K、阈值）只影响查询阶段，保存后即可用于后续检索。
- 调整配置后建议用固定的 20–50 条问题做回归对比，不要只看单次问答效果。

## 8. 常见问题

**Q：为什么分段长度不能设得很大？**
A：块越大，向量表达越“平均”，检索精度越低；同时会占用更多大模型上下文。长文档优先用父子分段，而不是一味加大块。

**Q：为什么调高 Score 阈值后经常搜不到内容？**
A：阈值过高会过滤掉本来可用的候选。先保持 0.55–0.60，结合 Top K 一起观察；不要用阈值弥补切块质量。

**Q：为什么已经保存配置，检索结果没变化？**
A：检查是否只改了分段/索引模式但没有重建索引。检索参数保存后立即生效，切块和索引配置需要重新入库。

**Q：Q&A 模式需要设置分隔符吗？**
A：不需要。该模式按问答结构切片，页面不提供额外配置。

**Q：元数据需要写进正文吗？**
A：不需要。正文保持原文，元数据作为独立字段存储；只把关键的“厂商/型号/版本/章节/命令”拼到向量化文本头部即可。
